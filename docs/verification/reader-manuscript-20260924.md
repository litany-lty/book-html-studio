## 1. 实际发现与修复

### 首屏读取的确定性错误

`reader.js::qualityOf` 在声明 `const transcribed` 前使用它，普通 READY 页即可出现 `Cannot access 'transcribed' before initialization`。异常被读取页的 catch 捕获，用户只看到“页面读取失败”，原有只检查 pageerror 的浏览器验收也可能看不到根因。

已修正声明顺序，新增普通 READY、模型转写、人工已校对三类质量标签的 Node 回归。当前页先取正文，再恢复随读会话/发导航通知和邻页预取。命中缓存不先清空正文闪烁；迟到滚动恢复检查书籍、页码及请求代次。只读邻页最多2个并发，省流模式不预取。

### 可理解性自检默认执行，但不挡住可读基础稿

旧实现基础稿生成前发一次云自检，增强后又发一次。新流程为：

`提取或识别 → 默认本地异常字符检查 → 基础稿持久发布并可读 → 自动语义自检 → 未确认疑点随版本化结果发布`。

本地检查不需要凭据，处理未识别占位符和替换字符，稳定issue ID防重复，人工确认不被覆盖。云语义自检使用既有Qwen凭据、服务端授权和同一次attempt预算，没有独立用户开关；缺少配置或授权时保留本地检查与原文，不静默追加供应商或取消权限门禁。

每组最多2000 UTF-16单元、最多8个片段，一页最多4组。缓存绑定书/页、原文、片段、冻结书内上下文、模型、端点及凭据摘要，最多64项。完整响应最大256KiB；损坏JSON、重复键、截断结果不记为完成。单组失败或预算不足时保留前面有效疑点，不重复发整页兜底。

疑点只接受当前组的block/slice身份、整数偏移、精确quote和合法UTF-16边界。偏移不符但quote在当前片段唯一时才可定位；多次出现的quote不猜位置。候选仅写inferredText，replacement保持null，resolved保持false，original/simplified不因“更通顺”而改写。古文、术语、专名、否定词和数字不得仅凭主题先验自动替换。

结构重排是另外的可选动作，旧Qwen辅助复选框改为“额外启用结构重排”。自动自检状态只进入质量详情，不再增加一个自检按钮或遮挡正文的面板。旧手动自检API保留为本地预览，返回原revision/commitId，不再把AI分析作为MANUAL_SAVE提交。

这不是对“文字完全正确”或“所有段落一定都已检查”的保证。覆盖上限或外部失败会明确DEFERRED/PARTIAL；任务覆盖率不是OCR准确率。已处理的旧页不会仅因打开就自动收费重跑，新处理或主动重试采用新链路。

### 遮蔽手稿：先得到有来源标记的转录，失败不丢掉已恢复区域

旧手写通道每栏转录、复核、联想补全，6栏可能串行产生18次调用，且记账失败仍继续发送、响应体未受同一物理请求包装保护。

现在每个区域仅一次首轮视觉请求，包含原色调缩放图和对比增强图；6个区域最多6次首轮物理调用。两个视图来自同一区域，只转录一次。裁切边界在附近低墨量行/列中选取，并使用不重叠的归属区域，避免跨栏重复和固定比例切断字符。竖排按右列到左列、每列自上而下；横排保留自然顺序。

原始PDF和输入图像不修改，不擦除防盗印或用生成图片补字。单区域按需创建栅格，长边最高2200像素；双图PNG合计不超过8MiB，并取得图像/编码资源租约。没有同时预先分配整页所有区域的Base64。

转录要求严格JSON。不能辨认的字保留□，完全不能转录的区域保留原图占位；模型核对结论也是未确认疑点，不作为真实字形证明。候选每处至多两个码点，不能用整句“补全版”混进正文。标注同时核对字符、原文位置与UTF-16边界。

第二或更晚区域失败时，保留已经恢复的区域，余下区域标记未完成并停止加发；第一块失败且没有任何有效正文时仍报未完成。远端错误、截断和审计失败都不装成识别成功。

手写转录和自检共用QwenPhysicalCall、并发门禁、物理回执、同一页级尝试预算和总期限。6次转录不等于整页必定只有6次收费，自动语义检查仍可能占用本次剩余预算；双图请求也不意味着每次费用更低。本轮没有实测供应商价格或识别准确率提升。

普通OCR返回少量文字也不再一律判为整页已完整识别：少于80字符、覆盖面积小于12%，且图像有疑似文字证据时，最多尝试2个附加区域；保留原始零星文字，避免向已覆盖区域重复贴入。真正空白、无文字证据的区域不无限重识别。不自动改用另一收费供应商。

用户所附808×580像素图片在本地做了无网络、非OCR的像素/连通区域检查，按ScanTextEvidence相同阈值得到nearBlank=false、possibleText=true；原始文件摘要前后相同。连通区域数不是字数或正确率。没有将该图提交到Git，也未宣称已经转录出其中所有文字。

### 调度、取消与远端作业

原PageWorkScheduler有无界队列、按“book:page”把不同attempt误当同任务，以及取消future时物理工作仍在写入的风险。现为64个活跃/排队页上限，后台不能占最后一个前台预约；各阶段队列有优先级和有限公平规则。

同页同attempt UUID/代次可合并提权，不同attempt在旧物理所有者退出前拒绝。基础稿与增强线程显式传递同一QwenExecutionScope，不能因切换线程重置预算或期限。取消只发一次中断，future和active登记保持到真实worker完成持久终结。JobService收到取消也等待底层完成，不提前释放页所有权或数据租约。旧基线后发生人工保存时，在发出增强请求前检查真实revision，不花费旧页请求也不覆盖人工内容。

远端名额满时先查找完全匹配书/页/供应商/账号/指纹的已有任务，允许续查，不先因总数3拒绝。超时只能证明“陈旧”，不能证明远端任务已结束。仅从未发送过的过期RESERVED预约可释放；已发送/UNKNOWN保留占位，不靠时间退款或重发。提交意图落盘失败时停止发送，不再忽略异常继续调用。 另补上发送状态栅栏：SUBMITTING/SUBMIT_UNKNOWN/REMOTE_UNKNOWN不能再次转成新SUBMITTING，即使复用相同句柄也不得再次POST；新增2项重复提交回归，相关20项测试通过。

## 2. 阅读界面收口

- 任务详情归入“任务”对话框，保留原处理设置、停止、失败页批量重试等能力，不占正文上方固定高度。
- 本页重处理合并为一个函数和一个默认入口；正常页在“本页”菜单中，失败页使用页头重试，删除任务头和正文内重复按钮。
- 未保存校对、保存中或版本冲突时不派发；包含人工确认的覆盖需明确确认。未收到处理接受结果，不把canonical Page改成PROCESSING，不清空已读缓存。
- 请求不确定时先同步任务，不重复发送；过期页面响应不贴到新书页。完成或失败后清理本页重处理意图，避免按钮永久停在处理中。
- 默认不替用户勾选整书处理；现有明确保存的选择继续保留。自动阅读仍核对服务端策略，不能只因为API Key已配置就外发。
- 专注模式继续隐藏箭头和边栏，保留边缘点击、键盘翻页及底部进度条。补测发现从原生任务对话框切入专注时固定布局可能失效，改由各实际布局节点同步focus类，不靠等待延时或强制重排绕过。

没有新增颜色体系、图标按钮堆叠或百分比动画。原纸面、字体、主题、字号与专注边缘行为保留。设计结果以实际桌面/手机浏览器检查为依据，不宣称经过眼动实验。
