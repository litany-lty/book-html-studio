## 2. 进度接口与阅读交互

当前接口仍是 **ProcessingSnapshot V2 的兼容扩展**，没有改名冒充 V3。`serverInstanceId` 标识实际服务进程；客户端保留有限旧进程集合，已淘汰进程的迟到响应不回写。

缺少内存快照时读取权威 attempt，显示 PARTIAL / UNKNOWN / INTERRUPTED 等真实状态。恢复快照使用 RECOVERED 阶段，前端不显示虚构的 0%、95% 或已完成百分比。当前可读内容与该次任务的可证明发布 revision 分开，不用当前页面 revision 猜测旧任务成功。

页级进度 GET 增加 ETag/If-None-Match；304 只复用当前书页已持有的响应，不解析空 JSON。请求超时仍覆盖完整响应体。

同一页只保留一个进度请求。可见页的活动任务每秒查询；空闲发现降为30秒。已知任务开始或标签页恢复可见时立即唤醒，不等待空闲间隔；隐藏时停止后续轮询。旧页请求结束不得清理新页的控制器、缓存或定时器。

## 3. 调度与恢复的边界

`PriorityTaskScheduler` 目前服务于 Qwen 协调器，不是整个应用已完成统一跨入口调度的证明。按已配置并发数限制工作线程，后台最多占用并发数减一，后台队列不能占最后一个前台排队位置。后台容量为0时直接延期/拒绝，不创建永远无法获得容量的等待任务。

父协调器不通过取消 CompletableFuture 假装物理调用已经退出。它等待登记的子任务完成真实收尾；网络许可继续由已有 QwenPhysicalCall 持有到响应流/账本收尾之后。结构调用也放入同一生命周期，关闭不再遗漏仍在同步等待结构的父任务。

旧账本临时文件仅对已知生成命名且非链接、非目录、大小在限额内的文件隔离。隔离保留原字节，不判定临时内容是否已计费；已有 SENT_UNKNOWN/PENDING/OUTCOME_UNKNOWN 完整保留。磁盘或权限不足导致隔离失败时仍停止新调用。

本轮没有增加永久统计/检索索引，没有取消账本全量校验，没有为不确定远端结果退款，没有新增自动跨供应商回退。
