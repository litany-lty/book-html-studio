# 来源日志检查点与已验证状态复用

基线：`main@19a15fdad0ef8d9fcea8b0d0a99eca95fd4d66ef`。本批只修改来源事件读取、恢复和派生检查点，不修改 OCR 策略、原文、授权、预算或前端交互。

## 1. 已复现的开销

`BookIndexService` 检查索引是否可用时调用来源水位和 `hasUnresolved()`；旧实现反复 `readAll()` 并解析全部 JSON。提交新页的准备、查找意图、结算也重复解析已结算历史。首批4项真实WAL测试在原代码上3项失败、1项对照通过，0执行错误，保留旧失败XML和日志。

本次使常用水位、未结算状态、最近事件、准备和结算复用同一份已验证投影。完整历史查询 `readAll/readSince` 和超出近期缓存的旧操作重放仍可走全量权威回放，不用“缓存不存在”推断原操作不存在。

## 2. 检查点不是新的提交权威

每本书增加可重建的 `source-checkpoint.json`，格式版本1。检查点只覆盖已封存段，保存明确的段名、字节长度、SHA-256，以及未结算操作、有限的近期结算和来源水位；自身内容另有完整性摘要。

冷加载先核验检查点结构、书籍归属、重复字段、整数类型、范围和摘要，再对其覆盖的每个来源段核对真实文件哈希；活动尾段仍由原WAL读取器校验帧CRC并回放。没有跳过原始文件的冷启动完整性检查。检查点缺失、截断、非法或内容不匹配时，从原WAL重建，不清空历史、不产生新的模型请求。

完整坏帧继续保留并拒绝；只有活动段的不完整尾部可使用原有恢复规则截断。检查点存在而全部来源记录或预期活动段缺失时，不把它重新初始化为0。符号链接不被读取或覆盖；检查点写入失败不推翻已经成功的权威WAL写入。

这是本地完整性校验，不是数字签名，不能防御有权限同时篡改所有WAL、检查点和摘要的攻击者。检查点不能证明某个页面已发布；页面恢复仍要求已有的精确 commitId/revision/hash 证据。

## 3. 正常执行和恢复

新的来源事件先在投影副本中校验身份和容量，再写WAL并强制落盘，成功后才发布进程内缓存。写入异常清除派生缓存，后续必须重新核验实际文件。封存切段后才保存该前缀的检查点，没有删除旧WAL。

同数据目录的多个句柄共享监视器与有限缓存。复用前比较来源文件身份、大小、修改时间和支持平台的ctime；回放前后再检查变化，避免将阅读期间被替换的数据误记为已验证。缺少可靠ctime的平台保守重新验证，不承诺相同的热路径加速。

未结算操作按自己的sourceSeq保存，不因更新页已成功而清除旧页的未知记录；晚到的旧结算也不使最高来源水位倒退。超出近期缓存的旧提交仍核对历史，重复结算不会追加重复记录。

## 4. 有界资源和准确性能口径

全局最多缓存8本书。每份来源投影最多512项未结算操作、128项近期结算，按保守对象估值限制为2MiB；封存投影与活动投影各有一份，不能把这个估值宣称为JVM总堆硬上限。待结算项超限时拒绝新的prepare，不淘汰未知债务来释放名额；已经存在的大积压使用原WAL容量约束内的慢回放，仍允许核对和结算，减少到界限内后自动恢复缓存。冷恢复的临时对象不在2MiB常驻投影估值内。检查点文件最大4MiB。

确定性回归使用实际来源WAL：270次操作共540帧，其中512帧在封存前缀、28帧在活动尾部。清空进程缓存后的检查点恢复仍核验封存文件的字节哈希，但只解析28帧来源JSON；数据不变时连续检查不再解析历史来源JSON。新准备和结算直接更新已验证投影，不为每次追加全量解析。

这些是具体工作量断言，不是依赖主机快慢的计时比值。目录/文件属性检查仍与段数量相关；冷加载仍读取封存文件进行哈希。因此不能称所有磁盘操作均为O(1)，也没有测得真实书籍首屏缩短多少毫秒。

原来的4096段、64MiB回放容量边界继续保留。本批没有实现WAL压缩、永久归档、历史删除、磁盘容量扩展或真正的逐页索引增量事务。超过容量需后续归档机制，不得通过删除来源日志来“恢复处理”。

## 5. 回归范围

新增 `SourceCheckpointTest` 覆盖热路径复用、冷检查点恢复、乱序结算、旧重复操作、跨句柄可见性、检查点损坏/跨书/重复字段/整数强制转换/路径越界、活动尾部修复、完整CRC损坏、封存段与整段历史缺失、写入失败、符号链接、待结算容量和回放期间文件变化。

另用隔离Java进程在来源事件已强制写入后 `halt(23)`，再由全新Java进程加载检查点和活动尾部，验证未结算任务仍存在。测试只退出临时子进程，不关闭用户服务或电脑；这不是硬件断电或文件系统目录fsync的完整耐久性认证。

交叉检查追加了513项历史未结算积压回归：不能让新缓存容量上限把合法旧数据永久卡在无法恢复状态。最终实现仅限制常驻缓存和新准入，旧任务仍可结算；不隐藏、淘汰或自动判成功。

新用例加入完整Maven回归与CI的三轮重复门禁；既有完整导航、校对工作台、专注模式、扫描回退及隔离Spring阅读冒烟保留。最终结果以受测提交对应的CI产物为准，两个原有私有样本跳过不计通过。未使用真实模型或用户原稿。

## 6. 升级、维护与未验收项

没有改变页面、来源事件WAL、授权或供应商配置格式。检查点是派生侧文件，完整WAL在场时缺失/损坏可重建；它不能代替完整私有数据备份。备份和恢复应保持书籍数据目录内部一致，缺失来源段时先恢复数据，不删除检查点来绕过保护。

本次不会重启日常服务，不修改真实书籍、密钥或私有配置。提交与合并后仍应核对main CI，再同步本地主分支，保留测试证据后清理本轮临时分支。
