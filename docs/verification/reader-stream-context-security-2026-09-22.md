# 阅读优先、书内语境与凭据安全整改

## 基线与交付边界

基于 `main@7aae566f23b9ba411702b6c85e02bfd332231325`；保留本次「宣纸墨青」视觉设计。整改分支 `audit/reader-stream-context-security-20260922`，不直接合并或覆盖主分支。

审查方法：全仓文件清单与静态扫描、完整 Java 回归、前端语法/契约检查，以及任务调度→OCR→分块校对→版本化提交→阅读显示的关键链路人工审查。这不是“逐行证明所有代码没有缺陷”，也不是生产性能或真实书籍识别率的认证。

## 1. 首屏与并发

`GET /api/books/{id}/metadata` 不再为了打开一本书而扫描全书页面；当前页正文取得并展示后，再加载全书统计、目录和任务信息。页级投影使用已缓存画像；冷缓存时使用保守空画像，不以全书画像构建阻塞当前页。画像缓存最多 64 本书，以条带锁与变更代际防止失效后的旧构建结果重新污染内存。

前端先请求当前页，再以两个并发 GET 预取相邻页；保留现有 16 页缓存边界。快速翻页、切书的旧请求经过书籍/页码/请求代际校验，不覆盖新页面；旧 GET 完成回调不会误删同一缓存键的新请求登记。省流模式不预取。

用户明确开启随读识别后，主通道当前页优先入队，最多当前页加两张邻页并发；当前页已经可读时，后台最多占两个槽，保留一个槽给当前页跳转或重试。已外发的计费请求不被强杀重发；旧当前页仍在执行而容量已满时，新当前页排在队首等待自然释放。默认只使用本次授权的主通道，配置了另一个服务并不等于同意并行发送。

Qwen 分块默认启用，但仍以用户明确选择辅助处理为前提。总请求并发、后台并发、队列与每页物理请求预算均有限。修改并发配置不替换正在持有的信号量；已占用请求自然结束，不会出现新旧限流器同时放行造成超发。

导入或打开书籍不自动发起付费 OCR；已缓存内容的默认加载无需授权。自动处理全书默认关闭，只接受用户明确设置；不存在把“当前页优先”解释为未经同意处理全书的行为。

## 2. 本书语境辅助 OCR

新增 `BookContextService`，一次校对尝试只构建一次有界上下文，包含本书标题、附近可靠章节标题与带页码/版本/来源的原文片段。最多查看 14 张页面记录、总字符预算 8,000，覆盖当前页、前 8 页、后 2 页和开头少量页；未处理页面不触发额外识别。

只选已就绪页面中人工确认或达到保守 OCR 置信度门槛、且没有未解决内容疑点的原文块；模型推断文字不作为新的“真值”回灌。OCR 置信度门槛是筛选条件，不是已经校准的正确概率。证据按固定书籍 ID 和页码绑定，跨书混入直接拒绝；缓存身份包含书籍、页码、上下文指纹、任务区间、模型/端点/凭据作用域和图像哈希。

模型提示明确：字形与原图优先；章节、术语和上下文辅助消歧；不得因语义顺畅而虚构原文。章节尚未识别时保留不确定性，不猜整本书主题。响应严格验证字段、整数偏移、UTF-16 边界、原文引用和分块归属；子分块的偏移映射回原始块，人工编辑仍受版本检查与确认流程保护。

当前实现不是全书向量检索或自动术语训练。长章节的标题不在已读窗口中时，上下文可能不足；这是可见的保守降级。尚未使用真实书籍与付费模型做识别率 A/B 实验，不能宣称正确率提升了某个百分比。

## 3. 页头真实进度

`#page-processing-progress` 是 `#page-save-status` 的紧邻右侧元素；两者使用同一不换行的小组。示例：`已保存  核对 · 50%`。

百分比的分母是**当前命名阶段的已计划任务单位**，不是整页耗时比例、全书进度或 OCR 正确率。完成/失败/跳过/取消的单位均属于已结束工作；失败会在详细说明及最终状态中保留。未知分母显示阶段文字，不用计时器虚构百分比。阶段切换可以重新从 0% 开始，并同时更换阶段名称。

进度聚合串行保护计数；最新任务按创建顺序而不是心跳更新次数选择。心跳不推进真实进展时间。最多保留 512 个任务快照，优先清理已结束任务；遥测容量不足不应破坏实际 OCR 与保存。可读状态只在版本化持久提交成功后发布。

批处理与随读均接入当前页状态查询；取消、异常、跳过或局部失败关闭对应任务生命周期。处理完成不等于文字无疑点；部分完成显示“部分完成 · 待核对”，不伪装成全部成功。

页级 GET 单路轮询，有页面/任务/快照版本隔离；页面隐藏时暂停请求。轮询不重绘正文，人工草稿、焦点和阅读选区存在时，新版本延后应用。

## 4. 安全整改

设置 GET 不再返回已配置的 API Key、Secret Key 或 Access Token，只返回是否已配置。浏览器密钥输入框不回填；留空保持原值，显式清除字段才删除。设置状态及凭据配置对象的可打印表示脱敏；决策异常调试不再打印可能包含请求头、签名地址或密钥的原始堆栈。

API 响应使用 no-store、nosniff 与同源 Referrer-Policy。写请求校验完整 Origin 的协议、主机、端口，拒绝 null Origin 与不合法 URL；跨站浏览器 API 访问和本地连接的异常 Host 被拒绝。无 Origin 的本机命令行调用保留。**这是本地工具的同源加固，不是公网身份认证、租户权限或生产 WAF 的替代品。**

模型请求体积有界，网络超时覆盖响应头后缓慢/停滞的正文读取。429 的重试每次都计入物理请求预算，释放并发许可后再退避；缓存命中不扣新的物理预算。已消费的分块调用部分失败时，保留可读基线，不再自动追加整页兜底调用导致预算翻倍。

`.gitignore` 覆盖运行时设置、环境覆盖文件、证书私钥和测试产物。CI 增加只报告路径/行号/规则、不打印匹配值的离线凭据扫描，浅历史不得标为历史扫描通过。

运行时本机设置仍保存在忽略目录并受文件权限保护；本次没有把它改造成加密保险库。仓库无凭据与磁盘加密是不同要求。扫描是启发式防线，不是数学上的“永不泄密”保证；所有已获取引用可达历史可扫描，GitHub 上不可达对象、外部备份和历史运行日志不在其覆盖范围。若发现曾泄露的真实凭据，应先吊销轮换，再另行授权历史清理，不能只删除当前文件。

## 5. 节省注意力

保留原有纸色、主题、阅读字体和渐进展开设计；页头只增加低显著度的小状态，不添加遮挡正文的蒙层、大进度条或闪烁动画。数字使用等宽数字特性，状态宽度预留；窄屏允许状态组整体换行，但“已保存”与处理进度保持相邻。深色主题使用语义颜色，不写死浅色文字颜色；尊重 prefers-reduced-motion。

这是基于减少视觉干扰、保持空间稳定、渐进披露与可访问性约束的工程设计，不声称已经完成阅读注意力的人体实验。离线 Chromium 检查 1440×1000 与 390×844 的真实 DOM/CSS，验证可见、右侧相邻、同行、无横向溢出；该证据不冒充完整应用端到端测试。

## 6. 回归与复现

```bash
mvn --batch-mode verify
node --test scripts/verification/reader_stream_audit.test.mjs
node scripts/verification/probe_display.js
node scripts/verification/probe_job_scope.js
python3 scripts/verification/secret_scan.py --self-test
python3 scripts/verification/secret_scan.py --history
python3 -m unittest discover -s scripts/verification -p 'test_*.py'
```

本次修复的具体回归包括：旧任务事件抢占最新进度、并发完成计数丢失、心跳伪进展、配置更新超发、缓存/分块身份混淆、UTF 偏移错误、同源端口/协议绕过、密钥配置回显、头已返回但正文卡死、部分失败后的额外计费、保存前宣布可读、读中切页的旧响应回写，以及当前页可读时预取挤占重试槽位。

远程 Java 17 回归还暴露了两处测试同步问题：共享增强栅栏可能由邻页先触发，CopyOnWriteArrayList 的子视图在并发写入时可能失效。改为当前页专属栅栏、不可变快照和终态事件等待，保留原有基线、人工编辑保护及生命周期断言。

凭据门禁同时执行 `scan_secrets.py` 的当前跟踪文件/敏感文件名检查与 `secret_scan.py --history` 的全部已获取引用可达内容扫描。历史命中的三个字符串经核实是其他测试分支中的明确占位值，只按精确值排除，不豁免整个文件或供应商前缀。

最终测试状态以本分支/PR 对应提交的 CI 和补充验证记录为准。现有真实样本依赖测试会按原规则跳过；没有连接任何真实云 OCR/JEV/Qwen 服务，没有消耗用户模型额度。本地完整 HTTP 浏览器 E2E 被 Chromium 管理策略阻止（ERR_BLOCKED_BY_ADMINISTRATOR），不记为通过。离线布局结果见 `reader-stream-audit/offline-layout-results.json`。
