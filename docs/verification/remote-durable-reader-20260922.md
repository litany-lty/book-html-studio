# 本机远程实施：持久重处理回执与增量统计

## 基线与实际范围

基于 `main@807f5b34215c0811ce9ca1e3658cb7ccbb844574`，在用户授权的 Mac 上创建隔离工作树修改。原项目目录发现落后于远程且没有未提交改动，已安全快进至该基线；未改动真实书籍、运行配置、密钥，也未重启日常服务。

本批落实三个已有缺口：显式本页重处理的跨重启幂等、保存结果与附属统计失败分离、书籍统计的有界增量更新。保留已有专注阅读、隐形翻页、底部进度、扫描漏识恢复、加密秘密存储、主通道授权与 CAS。不是整份 FINAL 所有项目完成，也没有把多个旧整改分支重新合并。

## 1. 显式重处理回执持久化

`PageAttempt.Journal` 升级为版本 2，同时存储权威页级尝试和 `ReprocessOperation` 回执。二者在同一个文件中原子替换，然后才提交工作队列，不采用“发出请求后再另写幂等文件”的顺序。

操作键按本书和 clientOperationId 哈希，不绑定临时阅读预约；客户端原始操作 ID 不作为路径或明文写入回执。请求指纹涵盖页码、供应商、版式、对开、辅助识别、期望版本及人工覆盖授权。不同尝试具有不同任务 ID，同一已接收操作返回原任务 ID 和已记录状态。

- 同书同操作 ID、同参数：即使换阅读预约或重启，只返回已有回执，不重新处理，不新增云请求。
- 同 ID 改参数：409；仍在进行的新操作要重新检查当前 revision、人工覆盖许可及活动任务。
- 原请求已接收但响应丢失：匹配回执先于新鲜度检查，避免任务自身推进 revision 后把合法重放误判为冲突。
- 队列拒绝：持久记录 FAILED，重放不自动再次提交。
- 进程启动发现未终结记录：标 INTERRUPTED，保留已有页面，不从 READY 或更大 revision 猜测该任务成功，不自动重发。

当前仅补齐 `requestReprocess` 的显式本页操作。批量集合和自动导航的持久幂等、全局唯一页级执行引擎、持久 commitId 事务以及供应商恰好执行一次均不在本批完成范围。

### 保存期限与容量边界

回执可重放期为 30 天；到期返回 410，需用户明确使用新操作 ID。每本书最多 4096 个回执，并受整个 journal 的 16 MiB 上限约束。到容量后新操作返回 429 或存储容量错误，已有回执仍可查询；不会靠重启或删旧 ID 来偷偷解除防重复收费保护。

本批不提供在线历史回执压缩或墓碑归档工具。到上限后需维护，不应手工清空 journal 后重放原 ID；后续归档必须保证旧 ID 不能被当作新授权。

### 持久化与升级保护

回执写入使用临时文件、文件强制刷新、原子替换，并尝试目录同步。取消收尾时保留并恢复线程中断标志，避免中断状态使自己的记录写入失败。文件系统不支持目录同步时记录一次脱敏告警，不把已经完成的替换报告为未保存；这不构成所有系统突然断电的耐久性保证。文件系统不支持原子替换时，新任务准入失败，不改用非原子覆盖。

读取拒绝重复 JSON 键、尾随数据、未来版本、错误结构、超大日志及符号链接；损坏不能被解释为空幂等记录。旧 intent-only 格式兼容读取，并保留尝试序号；旧版本未记录的历史操作无法追溯补造。

升级前备份私有数据。新版写入 Journal v2 后，不应直接用旧二进制继续写同一数据目录：旧写入器可能丢掉不认识的回执字段。恢复应同时使用匹配程序与完整备份。此版本未改变 SecretStore 模式或已有主密钥。

## 2. 页面保存与统计更新分开

`BookStore.commitPage` 成功后，人工保存和版本回退立即以返回的真实 revision 为准。后续书籍元数据更新时间或统计落盘失败，仅记录 `PAGE_SAVED_METADATA_STALE`，仍向调用者返回已保存页面，不再返回误导性的“保存失败，请重试”。

页面写入、历史归档或 CAS 本身失败仍然是失败；没有吞掉正文持久化错误。书籍统计下一次读取可重新计算；元数据更新时间可能暂时落后，不能将其描述为已经完整自愈的持久索引。

保存响应不再为了更新统计而扫描整本书。元数据更新只使用已缓存统计，缓存尚未建立时保留旧计数，由明确的统计读取重建。

## 3. 有界增量统计

新增 `PageStatisticsCache`，最多缓存 64 本书。`BookStore` 每次成功页面发布只发出包含旧页、新页和变更代际的轻量通知；统计对 READY/人工核对计数做差量更新。

构建使用书级变更代际：发布进行中为奇数，结束后为偶数。冷扫描与提交重叠时不回填缓存，避免“失效之后旧扫描又把旧计数放回去”。通知与元数据更新不持有跨锁的慢扫描，缓存更新失败不改变已提交页面。

冷启动首次请求完整书籍统计仍会扫描 N 页，未实现持久化完整摘要索引。已有轻量阅读入口继续优先当前页，不依赖这个全量统计。缓存建立后，单页变更不再触发反复全书扫描；未缓存的书也不在保存确认链路内强制扫描。

- 本批完整 Java 回归：556 项，0 失败、0 错误、2 项相同跳过；实际执行通过 554 项。
- 生命周期、并发、持久重试与统计专项连续 3 轮，每轮 58 项全部通过。
- 本机 Chrome 使用实际前端：专注模式 42/42、扫描回退 13/13；实际 Spring HTTP/队列/存储/设置冒烟通过，页面脚本错误为 0。OCR 为受控替身，没有真实云模型调用。
- 脚本检查包含设置 19 项、响应体 5 项、组合 Node 8 项及 Python 19 项。最初误对没有测试文件的 scripts/security 目录执行 unittest，结果为 NO TESTS RAN，不当作通过；安全测试实际在 scripts/verification 中执行。
- 5000 页检查是真实写入和读取的合成页面 JSON 文件，不是 5000 页扫描 PDF/OCR 压测。缓存建立后保存一页并读取统计，只调用一次 `readPage`；检查结果和耗时位于 `test-results/statistics-scale.json`。一次耗时不是生产 P95，也不能计算成端到端加速比例。
