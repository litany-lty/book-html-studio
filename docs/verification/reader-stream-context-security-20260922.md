## 已实施

### 1. 当前页优先，而非先等整本书

新增只读快速入口：`GET /api/books/{id}/reader`、`GET /api/books/{id}/reader/pages/{n}`、`GET /api/books/{id}/reader/pages/{n}/progress`。首屏先读书籍元数据和当前页；全书页摘要、目录和任务状态随后补充。快速页读取不等待全书展示画像构建；轮询需要画像时，仅触发合并、有界的后台构建。

打开书默认自动随读，恢复该书上次页码；只使用已配置且当前任务选择的 OCR 通道，不因配置多个密钥就并行发送到其他供应商。可在随读设置关闭自动开启。该默认行为来自本次产品要求，会消耗所选供应商额度；Qwen 保留原有显式辅助开关，JEV 不因此自动开启。

阅读窗口为当前页、前 3 页、后 5 页；翻页停留约 1 秒后送识。优先提交当前页，再让邻页与其并行，不等待当前页全部增强结束。每通道最多 3 页；普通预取保留 1 个前台槽位，当前页跳转可使用该槽。满载时等待自然收尾，不强杀已发出的计费请求。旧窗口尚未派发的工作丢弃，已在途工作只提交到其原书原页。

全书后台处理不默认开启。新选项键 `book_html_auto_process_all_v2` 避免把旧自动默认值误当作用户的全书付费授权。默认前端缓存仍为有界 LRU；预取不再重复请求当前页，旧请求的清理不会删除新一轮同页请求。

### 2. 基于本书/章节的证据，而不是按主题改写原文

新增 `BookContextService`，上下文含本书标题、可识别章节提示、临近原始段落、页码与 revision、证据来源标签。最多读取 15 页，缓存最多 128 项；不随整本书页数线性增加每次核对成本。回看至多 12 页定位章节，取临近前后 2 页，遇新章节停止跨章取材。

未人工确认的页只从 `sourceRecords.original` 取证；人工确认页可用其已审核正文。模型推断、候选文本和未经确认的展示改写不回灌为“原始证据”，也不混用别的书。标题/章节是弱先验；OCR 证据明确标记未核验，不把出现频率或主题一致当作字形证明。

接入 Qwen 分组核对、兼容的旧全页辅助以及 JEV 决策状态。仍要求原图/来源位置、已知候选、偏移和引用匹配；不放开 JEV 自动定稿权限。保留罕见术语、人名、数值、否定词与无法确定的候选，不因主题“看起来合理”就替换原文。

修正 Qwen 缓存身份，包含任务范围、父级文本、书籍上下文以及局部图/概览图摘要。上下文或图像改变不能复用旧核对结论。默认保真阅读不会因为切换简体显示而自动应用 inferredText；辅助候选仅在显式辅助阅读中展示。

限制：此版是有界的同书章节/邻域证据服务，不是全书语义索引或术语库。很长章节回看不到标题时会保守缺省；识别到的标题也可能受 OCR 错误影响。准确率改善需要真实书籍的人工标注留出集，不能凭单元测试声称已获得某个正确率。

### 3. “已保存”右侧的当前页百分比

新增 `#page-processing-progress`，与 `#page-save-status` 放在同一不可拆分状态组。窄屏让整组换行，不把进度与“已保存”拆散；无弹窗、遮罩、旋转动画或逐百分比语音播报。

进度基于实际阶段/已完成任务单位：准备 0%、OCR 入口 10%、基线发布 40%、结构 50%、分组核对 60–85%、校验 85%、最终发布 95%。只有任务成功且正式内容提交完成才到 100%；完整成功后安静隐藏。部分完成、失败、取消、中断不显示成功终态。

这些百分比表示工作流里程碑完成程度，不是时间估计、OCR 正确率或“所有疑点已解决”。远端 OCR 内部未提供更细进度时保持当前阶段，不用计时器伪造增长。已完成处理但仍有疑点时保留质量提示，不把“待人工核对”误算成后台任务卡住。

修正不同 attempt 按 snapshotVersion 比大小的错误；使用服务端创建代次选最新任务。进度计数原子更新、上限受计划约束，终态不再被迟到事件覆盖。前端按 book/page/attempt/version 隔离响应；刷新进度只读，不会隐式重试付费调用。页面发布仍遵守未保存草稿/冲突保护和阅读位置恢复。

### 4. 调度、重试和 Qwen 小任务

显式重试只排队一次，并再次经 requestReprocess 的 CAS/人工覆盖检查，不再同时直接提交和排队强制重试。operationId 指纹包含预期版本及覆盖授权；同操作重复请求不能重复送识。阅读 reservation 必须同时匹配书籍和 token，取消中的任务继续占用在途槽。

READY/FAILED 页重新处理期间保留原内容快照，直到提交新版本；进度与 Page 状态独立。发布 revision 取 BookStore 实际提交结果，修复基线/增强版本落后一位的问题。关闭服务等待工作线程收尾，避免退出时仍写目录。

分组 Qwen 设为默认实现（仍受辅助总开关控制），全局共享 3 个出站槽、后台 2 个、每页 attempt 默认最多 8 次物理调用，有界队列。429 释放槽位后退避；每次真正出站都计入预算，截断重组不重复预留虚构调用，失败/未知调用不伪装免费退款。动态刷新并发配置不重置在途计数。

分组失败保留原文并标注部分增强，不偷偷改走昂贵全页重试。进度随各组实际完成推进，不被按提交顺序收集结果的循环阻挡。

### 5. 安全与注意力设计

设置 API 不再回传已保存的供应商密钥；只返回是否已设置。输入框留空保持旧值，输入新值替换，原有明确清除操作保留。移除可能泄露上游内容的调试栈输出。浏览器 API 响应 no-store，加 nosniff、同源 referrer 与禁止嵌入头。

强化本机边界：API 的 Host 和远端地址须为 loopback，拒绝 cross-site；带 Origin 的写入必须协议、主机、端口完全一致，不再把任意 localhost 端口当同源。无 Origin 的本机 CLI 保持可用。这是单用户本机软件边界，不是公网多用户鉴权系统；不得直接公网暴露或借反代绕过边界。

`.gitignore` 补充环境变体、私钥/证书容器与运行证据目录。`scripts/security/scan_secrets.py` 扫描受控文本及所有可达历史 blob，报告仅含位置、行号、规则，不含值/片段；扫描不完整返回独立错误码。CI 检出完整历史执行，发现旧密钥应先撤销/轮换，再另行授权协调清理历史，不自动强推破坏协作。

运行时设置文件仍可能保存明文密钥，沿用现有本机文件权限保护；本次没有将其改成系统钥匙串/加密保险库。不要把 data、个人 .env、密钥文件、带密钥的日志/备份提交仓库或分享。扫描是模式门禁，不能证明编码、二进制容器、未知格式或不可达远端历史完全没有秘密。

界面继续沿用新提交的纸面配色与字体体系，不全面重做皮肤。保存、处理、质量三种状态各司其职，后台细节渐进展开，数字采用等宽宽度、状态组预留空间、支持 reduced-motion；正文和读者当前位置优先。这些是设计原则的工程应用，不是已经完成用户实验或眼动研究的结论。
