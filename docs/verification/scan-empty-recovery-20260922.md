# 防盗印／复杂扫描页的空结果误判修复

基线：`main@44b57c220f338db80c5707d1401dace55c80ab4a`。本批不合并其他审查分支，不修改供应商密钥或用户图书数据。

## 根因与实际边界

前端将“没有可展示的阅读块”直接说成“空白页或仅含插图”；这也覆盖了旧 READY 空页、文字被展示投影过滤等情况。后端原有 `isFigureOnly` 只检查供应商输出的块类型，不能证明图像没有正文；空的合法 OCR 响应又和坏 JSON/网络失败共用异常，恢复路径难以区分。

上传示例能看到网格、竖排手写和深色叠印。已在本地对这张 2048×979 图片调用本次图像证据算法：`nearBlank=false, possibleText=true`，检测到 776 个候选连通分量、覆盖 36 个分析格。**这只是触发条件验证，没有调用实际 OCR，没有证明所有被遮挡文字已经正确转录。** 用户图片没有加入仓库；回归图片由测试代码合成。

## 新处理链路

已授权的当前 OCR 通道 → 合法结果检查 → 没有正文时检查原图证据 → 疑似漏识才作一次最多四区的局部重识别 → 坐标回映与来源保留 → 可读部分稿／明确未解决。

`ScanTextEvidence` 在最长边 1,200 像素的副本上分析低墨量、微弱连贯笔画、去长网格线后的候选连通分量及空间分布。去线只作用于分析掩码；送 OCR 的裁图仍含原始水印、网格和笔画，不修复、生成或擦除原图。整体低墨量且不存在连贯微弱笔画才能确认近空白；零星粉尘允许忽略。

“疑似文字”是保守启发式触发器，不是已校准的文字检测概率，也不能精确区分复杂纹理插画与手写。存在误触发／漏触发边界，因此其他非空白空结果仍显示未解决或仅保留图像，不再向读者断言无正文。

`OcrNoTextException` 仅表示合法结构中没有文字。坏 JSON、缺字段、坏坐标、超时和权限错误不降格为空白，也不被恢复逻辑无限重试。拆分跨页时一个半页没有文字不会丢弃另一半已识别文本；空半页保留图像框并标记部分完成。两半均为空不再重复提交整张跨页图。

## 恢复约束

恢复使用本次实际选中的同一通道，复用现有客户端配置和用量链路；没有偷偷改用 Qwen/JEV 或第三方。已有显式额度不足切换授权逻辑不变，局部恢复失败不继续跨通道兜底。

最多四个区域、串行、少量重叠；竖排选四个竖条（从右到左），横排选四个横条，未知方向使用四个区域并保留不确定标记。每块坐标映射回完整原图，保持可追溯裁图；重叠归属按中心点所在的不重叠核心区确定，不因文字相同删除不同位置的重复用词。

这是最多四次**区域识别入口调用**，不是最多四个物理 HTTP 请求的承诺；供应商客户端原有重试和异步查询仍受各自配置控制。恢复检查 90 秒停止期限并向客户端传播取消信号；不在请求已经发出后承诺瞬时中止、免计费或无限延长。

`OCR_REGION_RECOVERY=false` 可以禁止这些额外区域调用；即使禁用，疑似含文字的空结果仍不能被当作成功的空白／纯插图。打开书或查看失败页不会自动启动恢复，必须通过既有主动识别／已授权随读操作。实际使用会增加有限的该通道费用，界面原有用量记录继续生效。

恢复出几个词不代表整页完整。所有恢复稿标为 `TEXT_PARTIAL`，保留原始图像块、未识别区域和 `[OCR_RECOVERY_PARTIAL]` 警告；人工确认前不得冒充完整转录。批任务为带错误／待核对完成，随读进度为可读的 PARTIAL，并停止可选增强连锁调用。若仍没有可靠转录，明确 `[OCR_EMPTY_UNRESOLVED]`，重试失败不能清空以前的可读稿；CAS、人工保护和版本门禁继续生效。

## 展示与存量数据

旧 READY 空结果立即改为“未提取到可读正文，不能据此判定为空白或纯插图”，并在阅读区域保留真实原稿。全部文字被过滤时明确“有识别内容未进入阅读排版”。旧 `provider+blank` 标记本身也不再作为新证据：只有本次新版图像门禁的 `[BLANK_EVIDENCE_V2]` 标记且没有原始文字记录时才显示近空白。

存量数据不会批量迁移或自动重跑。部署后，先打开误判页核对原稿，再点“重新处理本页”；恢复到的文字仍需核对。字体、阅读进度条和专注模式的边缘翻页不由本批重写。专注箭头隐藏／收窄留白在已有 PR #6 的 `1665c623` 中实现，不重复覆盖它。

## 验证

新增 Java 用例覆盖叠印手稿、网格手稿、普通合成笔画、真白纸、孤立尘点、微弱边注、纯网格、大片实色插画、取消、故障、恢复上限、坐标映射、原图像素不变、跨页局部空结果、实际处理管线、批任务旧稿保留和随读 PARTIAL。Node 用例覆盖旧空页、旧 blank 标记、过滤后空阅读、部分稿及失败状态。Chromium 检查实际 `reader.js` 渲染函数和 DOM，数据为合成，不能冒充真实后端／供应商识别率验证。

本地目标 Java 回归 38 项通过，Node 五项通过；本地全套执行曾因无 UTF-8 locale 造成跨进程中文断言失败（设置 locale 后该 13 项测试类通过），完整执行又在导出测试阶段超过执行时限，没有将其记为全套通过。本地 Chromium HTTP 被管理策略阻断，浏览器验收必须以隔离 CI 的实际结果为准。最终 Java17 全量及浏览器结果绑定 PR 的最新 SHA／测试工件，不继承旧分支 PASS。

剩余范围：真实供应商对防盗印／手写／复杂纹理样本的转录准确率、可靠方向检测、长段跨区拼接、大图与低配设备压力测试，以及运行时凭据加密，均不宣称本次完成。完全不透明遮挡下原图没有保留的笔画无法从图像可靠恢复，不能用主题猜测填补后作为原文提交。
