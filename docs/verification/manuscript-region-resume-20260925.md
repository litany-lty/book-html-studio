# 手稿区域续处理：成功证据复用与有限持久记录

日期：2026-09-25。基线：`main@dc69c5c218024d536b19ae07c29b2511ba479f47`。
范围：既有“手写／影印稿转写”通道，接入已发布的页级执行引擎与调用账本；不切换用户的 OCR 供应商，不新增自检配置开关。

## 1. 修复的真实缺口

旧实现六区逐个请求。前一区域成功、后一区域失败后，再次显式处理仍重做全部区域；取消或重新创建服务也不能利用已经完成的转录。

先在旧生产实现运行4项隔离回归：3项行为断言失败、1项图像变化对照通过，0执行错误。失败XML和日志保存在仓库外；随后接入真实存储依赖，不修改预期。

现在每个取得合法完整转录的区域保存独立证据。同书、同页、原始渲染像素、阅读方向、完整裁切方案、模型、端点与转录／预处理契约一致，且未超过保留期时，新的显式重处理复用成功区域，只请求缺失部分。

**例：第1区成功，第2区限流中止。再次处理只需5个新的区域请求，而不是重新发6个。** 这是确定性传输测试的发送次数，不是实际模型耗时、计费或识别准确率测量。

## 2. 与“重新识别”的区别

并非永远使用同一缓存。如果整页转录已经完整发布，之后用户主动“重新处理本页”仍发起新识别。

判断已经发布时同时要求页面revision高于该次转录开始版本、lastCommitId存在，且完整原始转录sourceRecords摘要相同。不能仅凭READY或“某个较大版本”猜测已发布。

如果六区已完成、但进程在整页发布前中断，已有完整证据仍可重组，无须重新请求模型。部分页已经发布，也仍可继续缺失区域；缓存自身不发布页面，不修改人工稿，原来的提交身份、CAS、人工覆盖确认不变。

## 3. 可信与费用边界

每次复用仍保留“模型推断、待核对”和既有疑点，不能变成人工确认。空结果、只有□、定位字段不完整、截断／过滤或非法响应不作为完整区域缓存。看不清的字符不凭上下文补造。

复用计入已有UsageLedger的CACHE_REUSED，不新占网络并发、不扣新的物理发送预算、不虚构token或零费用。复用回执写入失败不会退而另发收费请求。未完成区域继续经过现有授权、共享并发池、当前尝试预算、取消和总期限检查。

正常调用的模型/端点/凭据在方法入口固定；凭据只留在当前调用内存，不写入续处理记录、正文或日志。原图指纹按分块RGB字节计算，不生成额外完整图片副本。

## 4. 持久记录与恢复

新增私有派生文件：`books/<bookId>/manuscript-resume/<page>.json`，格式版本1。包含转录文字与未确认疑点JSON，**仍属于私有书籍数据**；不保存图片、API Key或明文端点，不能提交到Git或公开证据包。

单页最多6个区域；每响应最多24576个UTF-16单元、文件最多1MiB；每书最多64份记录。硬保留期7天，只在使用或容量维护时检查，不是后台定时清理。容量压力下最多检查4个记录，只淘汰已验证过期、或精确证明已完整发布的证据；新的未完成记录不为了腾空间被清掉。

文件通过有界读取、严格整数／重复JSON键、书页身份和内容摘要校验，写入复用force、读回核验和原子替换。旧会话保存必须匹配当前文件的ownerId，不能覆盖新尝试的记录。

损坏、错误归属、符号链接或空间不可用时，缓存不作为转录使用，坏文件不静默覆盖；显式任务仍可正常识别，并在页面诊断里说明续处理记录不可用。缓存保存失败不丢弃已获得的有效文字。此派生记录不是权威调用账本，不能代替远端任务核对。

完整性摘要不是带密钥签名，不能抵抗能够同时改写所有本地数据及摘要的攻击者。每书64MiB是这些有效记录的逻辑上限，不是包括临时文件、其他书籍、原图和应用全部数据的全局磁盘上限。

## 5. 已补回归与验收口径

新增32项Java测试：手稿真实适配器20项，持久记录12项。覆盖部分重试、完整未发布复用、完整已发布重新识别、图像／模型／端点／方向／书页隔离、缓存账本和预算、未确认状态、损坏／容量／链接、旧写者保护、时钟和保留期。

另覆盖真实Java子进程：区域证据force完成后halt(23)，再由一个全新JVM恢复。未中断日常服务，也没有对用户电脑断电。这不构成硬件断电耐久认证。

转录响应额外拒绝围栏外尾随内容和不完整UTF-16字符；业务验证仍在实际请求成功结算之前。32项已加入CI的三轮重复门禁。完整Java、原有导航/校对/专注/扫描浏览器及隔离服务结果，以最终提交的实际产物为准。

## 6. 尚未完成与升级注意

本次是手写转写区域续处理，不是逐区域立即发布到阅读页面，也不是百度普通OCR区域恢复或语义自检组的跨重启续处理。首次识别仍使用既有六区顺序，不宣称真实遮蔽字准确率提升、计费降低幅度或大PDF首屏性能已经验收。

默认可理解性自检继续执行；新的缺失区域调用和自检仍共享现有预算，不凭复用增加调用限额。未做新的自动后台重试：启动、打开旧页或发现缓存不会自行创建收费任务。

新能力只对升级后产生的区域记录生效；旧版没有保存过的成功区域无法凭旧页面猜测补造。启用前备份整个私有数据目录；主页面、授权及调用账本格式不变。原有人工稿/提交保护不依赖此缓存，删除缓存只丢失可复用证据，不应作为修复权威日志错误的方法。
