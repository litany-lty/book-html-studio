# 阅读缓存、就绪页读取与轻量书架接口

日期：2026-09-25。基线：`main@a163188ee0de574ac31f7fdca682549293112af3`。
本轮只处理本地阅读数据获取/缓存，不改变模型授权、自动处理开关、人工提交保护或私有数据格式。

## 1. 已实施

### 阅读缓存估算与容量准入

旧估算遗漏sourceRecords、simplified、展示投影、候选文本及大量坐标数组，32MiB阈值无法反映这些对象。本轮改为非递归遍历JSON对象图，字符串按UTF-16、数组槽位及对象/属性计入保守估计；同一对象引用只计算一次。深层、循环、异常访问器和过大的图都有界处理，不执行getter。

大型预取页在准入前超过预算就拒绝缓存，不再先把正常邻页全部淘汰、最后才淘汰大页。字节统计使用有界重算，避免多个超大保护项导致减法误差。当前可见页或保护草稿依旧不得被淘汰，因此它们单独超过预算时允许例外；这不是浏览器实际堆大小的严格32MiB保证，也不是减少已经渲染的正文。

### 就绪页读取窗口与响应身份

即使后台快照给出5000个READY页，前端也只对当前页和前后各5页安排只读GET，最多11个不同目标；不再把全书依次读入12页LRU。当前页仍按最高优先级排入已有的3个就绪读取槽。

同一页处于GET在途时，新快照仅提高所需revision，不新增重复队列项。旧版本、错误页号或非READY响应不交给正文，也不登记为成功读取；下一次正常状态轮询可以重试GET，不重复云端POST。已有缓存较新时不倒退。API.page同时核对响应页号和blocks结构，避免将第39页响应按第1页展示。

### 轻量书架查询（后端已就绪，默认首页尚未接入）

新增只读`GET /api/books?view=reader`，只列出持久书籍元数据，明确附带`countsStatus=SNAPSHOT`。不调用统计刷新、索引校验、读取Page JSON或模型服务。它仍是O(书籍数量)的列表，不是分页目录。

原`GET /api/books`及其实时统计语义保持不变。`api.readerBooks()`已提供，书架卡片可标注快照计数；但app.js的首页初始化尚未切换到新接口，因此不能宣称首页已消除全库扫描。当前API.page校验和reading-window缓存修复已经被现有业务实际调用。

## 2. 明确没有落地的导航整改

整组app.js导航编排改动被执行工具拦截，未写入；本轮没有换工具或绕路执行该项。以下问题仍由真实前端延迟注入测试复现，保留原断言：

1. 首页仍等待普通全量书架接口，而不是新的轻量查询。
2. 配置读取缓慢时，初始化Promise.all仍可能延后书籍选择列表显示。
3. 切书等待新manifest时，旧书内容没有立即隐藏。
4. 同一等待期间，旧书的页码操作仍可能被接受。
5. 任务完成后的refreshBookData仍等待全书元数据/目录，才刷新正文。

`python3 scripts/verification/browser_reader_load.py`默认是完整诊断：当前仍应报告以上5项失败，不是发布门禁全部通过的证据。`--identity-only`仅运行本批已修复的响应页身份场景和无脚本异常/无写请求/无外网请求检查，4项；CI明确选择此范围。没有将五个未修复断言改成成功或伪装为跳过。

## 4. 接续事项与保护

本轮不改app.js，不声称当前页等待链全部解决。优先接续上述5个有实际复现的导航问题，再继续来源WAL检查点、真正索引增量事务、区域即时发布/仅续缺失区域，以及Paddle/PP-OCR/JEV共享调用入口。
