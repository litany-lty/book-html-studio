## 本轮专门修复

### 1. 防盗印/网格/手写页不再从空 OCR 推断成空白

“没识别出正文”“供应商给了 figure/table 标签”“版面过滤后没剩正文”和“图像确实近空白”不再混为一谈。

`ScanTextEvidence` 在最长边 1200 像素的只读分析副本中检查墨量、连通笔画和分散区域。即使整体墨量很低，一个成片的浅色笔画也会否决近空白。网格长线只从临时分析掩模中排除，**不修改、擦除或重绘原图，也不移除防盗印**。这个启发式只是补识触发信号，不是手写识别模型或文字正确率。

用户提供的防盗印截图在本地运行该检查，结果为 `nearBlank=false, possibleText=true, glyphComponents=776, occupiedCells=36`。这只验证原图不会被新的空白证据检查认可，不代表云 OCR 已恢复截图全部文字。原书截图没有提交进仓库；回归采用合成笔画/网格/大面积遮挡夹具。

已主动开启的 OCR 遇到疑似文字却没有正文时，在已选择的同一通道上最多增加 4 次区域操作（有少量重叠、归属核心和全页坐标映射），不自动切换供应商，不无限递归重试。开始前及每次调用后检查取消/总时限。供应商内部 HTTP 重试是另一层，不能把 4 次区域操作宣传为至多 4 次物理付费请求。`OCR_REGION_RECOVERY=false` 可关闭额外补识，仍保留空白误判防护。

部分区域恢复成功后，后续区域发生网络、额度、超时或格式故障时，停止新增调用，保留已校验的先前片段及未完成区域。全空、无原图证据或协议错误不伪装成功。两半扫描漏识一半时保留对应区域，不能只展示成功一半并宣称完整。

原始来源、图像、区域坐标和未校对标记保留；恢复结果为 `TEXT_PARTIAL` / `PARTIAL`，不把模型转录变成“人工已确认”，不追加整页兜底收费调用。旧版本已保存的 `+blank` 标签也不能单独证明空白；必须有新版证据标志且无正文/来源文字，才显示“近空白”。打开旧误判页不自动产生补识费用，请主动重新处理该页。

### 2. 两套进度与执行引擎的实际交界

批量处理也登记正式 PageAttempt，进度采用同一 generation，不另造与随读冲突的任务序号；成功可读状态使用持久提交返回的 revision。取消、异常、候选被拒、人工编辑冲突均收尾。

补齐 `EnrichResult.complete=false` 向任务及恢复日志的传播：有未完成分块不能因基础稿已 READY 就报告增强成功。冻结计划中尚未结束的单位不能由一次 finish(SUCCEEDED) 自动凑成 100%；非分块的 PAGE 单位仅在实际提交后结束。

前端新增使用 attemptSeq 的新旧判定；兼容旧服务时才看时间，无效时间和旧尝试不能顶掉新快照。同一尝试已经结束后不允许迟到 RUNNING 复活。百分比为阶段/工作单位加权，不是 ETA、耗时比例或 OCR 正确率。

### 3. 专注界面

进入专注自动显示解析后的阅读视图，隐藏页头及工作台。箭头与按钮列均不显示，正文使用 12～28px 阅读边距而不是固定 44px/8vw 翻页列。左右点击通过阅读容器事件判断，没有透明按钮覆盖文字。

单击边缘上一页/下一页，双击选词、已有选区、长按、往返拖动、滚动、正文链接和底部滑块不误翻页。短延迟用于区分双击选词；键盘方向键保留。底部进度条、页码和退出入口持续可达，正文末行不被底栏遮挡。

### 4. 安全与局域网兼容

普通配置只保存秘密引用。默认 ENV_ONLY 从外部环境读取，网页密钥控件只读；ENCRYPTED_FILE 使用仓库外的 32 字节主密钥与稳定部署身份进行 AES-256-GCM 认证加密，支持网页只写更新/显式清除。已有迁移、权限、单写者租约、错误主密钥拒绝与失败恢复测试保留。

默认 `BIND=127.0.0.1`。主动 `BIND=0.0.0.0` 时，可用同一局域网实际目标 IP；通过 `MacBook.local` 等名称访问需显式设置 `BOOK_ALLOWED_HOSTS=MacBook.local`。不接受通配符、跨端口或跨协议 Origin。此防护不是多用户认证；仍不应裸露公网。

密钥扫描同时覆盖当前跟踪文件与已获取可达历史；浅克隆直接标 INCOMPLETE。只对三个已经核验的测试占位字符串精确排除，不按 test-/your- 前缀或测试路径豁免。未检查不可达对象、外部备份、旧日志及未知编码，零命中不等于绝对无泄漏。

### 5. 首屏自动识别授权与并发观测口径

已配置通道只允许读取其可用状态，不代表授权付费识别。新浏览器默认关闭“打开书籍自动开始随读”；用户明确勾选后保存的偏好仍有效。真实前端回归使用“通道已配置、未授权”夹具，断言打开书籍没有写请求；实际服务端随读测试则显式设置授权偏好。

当前页优先以调度器实际接受任务的顺序核验，同时验证当前页与邻页尚未完成时已并行在途。不同工作线程的日志或模拟调用记录可能被线程调度颠倒，不能用 1ms 的记录先后代替准入顺序。本轮为测试服务加入真实准入观测，并增加刻意颠倒工作线程记录但仍要求当前页先准入、邻页可并行的回归；没有串行化 OCR 或取消当前页优先断言。物理网络到达供应商的顺序仍不能由本地调度优先级绝对保证。

## 升级与使用

1. 先备份整个旧数据目录到仓库外私有位置。旧备份可能含明文密钥，须保护访问，不能上传 Git 或工单。
2. 希望继续在网页保存凭据：启动前设置 `BOOK_SECRET_STORE_MODE=ENCRYPTED_FILE`、仓库外注入 `BOOK_SECRET_MASTER_KEY`（随机 32 字节的标准 Base64）、稳定的 `BOOK_SECRET_DEPLOYMENT_ID`，保留 `BOOK_SECRET_KEY_ID`。主密钥不要打印、贴到聊天或与密文备份存于同处。
3. 默认 ENV_ONLY 用户需先在环境配置供应商凭据。旧明文配置不能在没有相应目标环境/主密钥时盲目迁移；失败会拒绝加载而不是静默清空。
4. 启动后查看设置存储模式。打开之前误判页可先看到保守提示和原稿；对该页主动执行重新处理，已有人工校对内容仍需原来的覆盖确认。
5. 已有加密配置不能直接回退到只认识旧明文文件的二进制；恢复必须使用匹配的程序、完整配置和对应外置主密钥。

## 集成验收命令与明确边界

`mvn --batch-mode verify`；既有三个循环生命周期专项；`probe_api_lifecycle.mjs`、`probe_page_progress.mjs`、`probe_settings_secrets.mjs`、`probe_scan_empty.mjs`、`probe_focus_reading.mjs`；Python 回归与 `scripts/security/scan_secrets.py --history`。

只读 Reader integration 工作流验证真实 Chromium 的专注界面和旧扫描结果回退（合成 HTTP 响应），再运行实际 Spring HTTP、队列/存储、设置和当前页优先的浏览器冒烟（OCR 替身）。不得把合成接口浏览器测试记为真实云服务或全系统性能测试。最终记录以对应提交工作流为准。

本地 Ubuntu 容器使用 Java 21 编译 release17 并回归；最终 GitHub CI 使用 Temurin Java17。容器无显示服务器及 UTF-8 locale 的首次运行失败已通过仅调整运行环境复核，没有删减业务断言。容器 Chromium HTTP 受管理策略阻止，浏览器验收只认随后真实运行的 GitHub Actions 结果。

仍未验收：实际付费 OCR 对用户图的逐字正确率、不同书籍人工标注留出集、Windows/macOS 与真机 Safari、5000页生产负载 p95/峰值内存、完整物理调用账本和长期断电恢复。整份 FINAL 的持久幂等、唯一执行引擎、commitId 恢复事务、增量索引及 V3 严格协议不是本次全部关闭范围。合并 main 不自动代表可以公网发布。
