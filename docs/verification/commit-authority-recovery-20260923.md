# 页级提交权限与提交意图恢复（2026-09-23）

## 基线、范围与不变量

基于 `main@11ff366e29fa0e438965dcf703f390d726627bdc`，承接已合并的跨重启重处理回执、增量统计、SecretStore、扫描漏识保护与隐形边缘专注翻页。本批不改变 OCR 供应商、外发授权、真实凭据、真实书籍或日常服务。

本批关闭的是**任务结果发布的权威身份检查、已发布页面的提交意图日志与进程崩溃恢复**。不是完整唯一执行引擎、全供应商物理调用账本或整份 FINAL 的完成声明。

## 1. 原有缺口与现在的提交权限

旧存储层允许同一 `reading:reservation` 前缀参与提交，无法单靠持久条件证明“这个页的这次尝试”仍拥有写权限；原 `expectedSourceHash` 又只取第一个来源块的 ID。现在：

- `AttemptAuthority` 与 `BookStore` 使用同一数据目录提交锁；准入、撤销和终结均由存储层读改写，不再在任务服务维护第二份独立权威日志。
- 准入记录精确书页、attempt UUID、递增 generation、完整已发布页内容 SHA-256、来源 PDF SHA-256、父任务 ID、允许操作和人工覆盖授权。
- 实际提交必须携带 `attempt:<UUID>:<generation>:<outcome>`。仅有父任务 ID、预约前缀、其他页 ID、旧代次均不能发布。
- 锁内再次检查当前任务未取消、attempt 未终结／撤销、操作已获准、书未归档、revision 与来源仍一致。人工更新优先，猜中较新 revision 也不能复用旧结果覆盖。单个疑点的已确认修订也算人工内容，即使整页尚未标 reviewed，也必须明确授权才能重新覆盖。
- 增强结果必须接在**本 attempt 实际发布的基线**之后，校验基线的 commitId、revision 和内容 hash，不使用 `revision + 1` 猜测。
- 逻辑取消先撤销发布权限，再等待物理 worker 收尾。同 JVM 同一目录的多个存储句柄共享撤销集合；即使取消记录写盘失败，仍不允许迟到结果从另一个句柄写入。

来源 PDF 首次按真实字节计算 SHA-256；32 项缓存仅在文件身份、修改时间与 change-time 均未变化时复用。缺少可靠 fileKey／change-time 的平台每次重新计算。大文件散列在提交锁外执行，锁内只作元信息二次确认。该缓存不是防御有能力任意修改本机文件和伪造文件系统元信息的管理员；仍要求源文件由应用管理，不在处理期间外部原地改写。

## 2. 页级提交意图

已发布页新增 `lastCommitId`（旧页缺省为空）。`pages/commits/<页码>.json` 每页最多 16 条、64 KiB，仅存身份、版本、内容 hash 和状态，不保存密钥或第二份正文。新页面记录格式版本 2，attempt 日志版本 3，提交日志版本 1。

顺序：验证准入 → 持久化 PREPARED 意图 → 归档旧可读版本 → 写临时新页、force 并校验 → 原子替换页面 → 写 COMMITTED → 发布轻量页变更事件。

## 3. 恢复和重复提交的真实语义

| 中断位置／证据 | 恢复结果 |
| --- | --- |
| PREPARED 后、页面替换前；旧页版本和 hash 完全匹配 | 标记 NOT_PUBLISHED；旧页逐字节保留，未终结尝试标 INTERRUPTED |
| 页面已替换、完成记录缺失；commitId + revision + 内容 hash 全部匹配 | 补记 COMMITTED；仅按该次发布所记录的结果结算对应尝试 |
| 只发布基线，增强尚未结束 | 保留可读基线，不能声称增强成功 |
| 已发布部分结果 | 恢复为 PARTIAL，不提升为 SUCCEEDED |
| commitId 相同但正文不同，或无法验证证据 | UNKNOWN／拒绝新增写入，保留原页与日志，要求核查 |
| 旧版仅有 READY 页或较大 revision，没有准确提交证明 | 保守标中断，不猜成功 |

恢复不调用 OCR、不重新提交模型请求、不重新生成正文。相同已发布 attempt／操作／输入版本／内容／结果重复提交，只返回现存匹配页面，不追加 revision、历史或统计事件；改了内容、换了旧身份或当前页已被其他操作更新则拒绝。这里只保证本地结果发布的幂等，不宣称远端模型“恰好执行一次”。

页面已经原子替换成功后，完成记录写失败不会伪装成“保存失败，请再提交”；恢复按真实页面证明修复。无法判断页面是否替换的 I/O 异常，先读取并校验实际页面，不直接把异常当作“肯定没保存”。未解决 PREPARED／UNKNOWN 不会被日志容量淘汰。已结算旧条目滚动保留 16 条，不是完整审计历史替代品。

使用原子替换与文件 force；不支持原子替换的文件系统拒绝新事务，不静默降级为非原子覆盖。目录 force 不受支持时记录平台限制。实际硬件断电、磁盘控制器缓存、网络文件系统和外部管理员并发改文件未得到耐久性认证。新导入页仍沿用已有导入发布标记，不是每个 PENDING 页建立一次更新事务。

## 4. 测试口径

新增页级权限与发布测试覆盖串页、伪造／过期 attempt、序号错误、同预约旧结果、权限操作不匹配、原稿同大小／同 mtime 替换、同块 ID 原文变化、人工更新、取消落盘失败、真实基线归属、只读重放、部分结果、JSON 数值强制转换、日志损坏及容量上限。

另有 3 项子进程测试：在全新临时数据目录启动独立 Java17 进程，在“意图已落盘”“页面已替换”“完成记录已写入”三个位置让**该测试子进程**直接结束，再由另一存储实例恢复。测试不终止用户服务、不开网络、不涉及真实书籍。这是进程异常退出实验，不是实际硬件断电实验。

少量旧测试原来主动写 JOB_START／PROCESSING，已改为正式 attempt 准入：保留取消后 409、原内容不变、人工接受被占用拒绝等断言，不恢复已废弃的页面处理中间态写入。页面包含数组字段，跨序列化一致性比较使用完整 JSON 值而不是数组引用相等。

本机 Java17 完整离线回归：584 项，582 项实际通过、0 失败、0 错误、2 项既有私有夹具跳过。新增 28 项全部通过。生命周期／并发／回执／统计／提交权限／进程恢复专项连续 3 轮，每轮 86 项通过。30 条离线脚本命令全部成功，包含原 JavaScript 行为探针、语法、Python 自测与单元测试。

正式 CI 的三轮重复门禁同时加入本批新测试；最终受测 SHA、构建清单、扫描结果、浏览器产物与合并状态以本批 PR 及合并后的 main 工作流为准，不把本机 PASS 当作尚未执行的远程结果。

## 5. 升级、回退与下一批

先停旧服务并备份私有数据，再用本批或更新的 main 启动。旧 page／attempt 文件只读兼容；新任务写入绑定信息时日志升级到版本 3，正常更新页面时写版本 2 和提交日志。不要让旧二进制写入同一目录，否则其重序列化可能丢弃新身份字段。需要回退时恢复完整匹配的程序与备份，不能只复制几份 JSON 或删除日志绕过拒绝。

提交日志 UNKNOWN 的页面允许保留并读取原文，但拒绝新的结果发布。应检查对应页文件、历史和提交日志，恢复准确备份；本批没有提供能安全猜测缺失原文的“一键修复”。旧的 30 天／4096 条重处理回执保留规则不变；16 条提交日志不是回执删除策略。
