# JEV：响应完整性、取消传播与调用回执整改

日期：2026-09-25。基线：main@f9e546a6d3ae00e792f9e8f7d8d2dbef4c7df517。
范围：现有JevDecisionClient内部的响应验证、方法总期限、取消和回执结算。不修改真实书籍、密钥或运行配置；不调用收费模型、不重启日常服务。

## 1. 实际复现

首批11项隔离回归在基线上有10项断言失败、0项执行错误；大整数溢出用例原来已拒绝，作为保留的边界对照，不计为新发现。

- 已取消的调用仍能发送并返回成功；准备回执期间取消也没有阻止发送。
- 传输IOException后没有终结原SENT_UNKNOWN记录，异常cause可能包含供应商细节。
- 收到响应后发生取消，旧逻辑仍返回可采用的决策。
- 合法答案后附加第二段JSON仍可接受。
- token数量为小数时被截断为整数；Score的非数字confidence、非对象probabilities被忽略。
- 响应含业务error但同时带answers时仍可能通过。
- 注入的传输不执行大小约束时，客户端没有第二层响应长度检查。

复现原始XML与失败日志保存在仓库外book-html-studio-verification/jev-call-boundaries-20260925。两次编辑脚本的字符串/REPL语法错误没有改动生产文件，之后使用正常脚本完成修改；不将工具错误计为业务缺陷或通过证据。

## 2. 本批实际修复

一次调用使用从方法开始计算的单调总期限，覆盖请求序列化、准备/发送回执落盘、传输、解码和业务校验。网络请求仅获得当前剩余时间，不能在慢磁盘或序列化之后重新开始完整期限。

新回执首先保存PREPARED，发送前保存SENT_UNKNOWN并再次检查取消/期限。证明没有调用传输时保存NOT_SENT；传输已开始但结果不明保存OUTCOME_UNKNOWN；取得完整响应但校验失败保存FAILED。任何状态写入失败都不伪造成功、自动重发或自动退款。

最终收尾暂时清除已有线程中断标志，仅为了让该调用的回执有机会持久保存，完成后恢复中断。若取消发生在成功回执落盘过程中，保留物理请求已完成的回执，但向调用方返回取消，不交付可采用的推荐。

问题定义在序列化前复制成不可变映射，响应按同一题目集合校验；等待期间修改调用者的Map不能改变已发送请求的判定契约。

JSON解析拒绝重复键和尾随文档，按原始响应字节解析；业务error、题目类型/数量、候选别名、概率及分值仍按既有规则验证。token只接受非负、可由long表示的整数；评分的可选字段一旦出现，就必须有正确类型，不能把非法字段当作缺省。

请求通过有界输出流序列化，不在生成无限完整字节数组后才发现超限；请求上限8MiB、响应上限32MiB是安全绝对上界，仍执行调用方传入的更小上限。最多64道问题，期限最多600秒；这些是本地保护值，不是供应商服务规格。

已返回的合法token在后续业务校验失败时保留，缺失或无效值不写成0。错误类型保持原有PROTOCOL/UNAUTHORIZED/RATE_LIMITED/NETWORK/TIMEOUT/CANCELLED等分类，异常消息及cause不携带原始响应、密钥和传输详情。
