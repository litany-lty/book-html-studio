## 2. 阅读加载与并发

### 2.1 首屏不再等待全书

仅把浏览器的请求顺序改成当前页先发是不够的：原 `BookService.get()` 会重算全书统计，原单页投影在冷缓存时会调用 `buildProfile()` 扫描全书。本轮同时增加后端阅读快路径。

- `GET /api/books?reading=true`：持久化书架元数据，不扫描每一本书的全部页面来重算统计。
- `GET /api/books/{id}?reading=true`：只读取本书元数据。
- `GET /api/books/{id}/pages/{n}?reading=true`：当前页内容、轻量疑点索引、缓存投影或保守本页投影；不等待全书画像。
- 旧的、不带 reading 参数的接口保持完整语义，供现有客户端和完整统计使用。

`BookPresentationService.profileForReading()` 在画像未就绪时立即返回保守投影，并通过 **1 个工作线程、16 个排队位置**执行本地画像重建。相同书的重建合并；目录、摘要与后台请求共享 single-flight。画像缓存最多 32 本。缺乏跨页证据时不凭空隐藏文字。画像生成后，目录响应和随读轮询逐步补齐展示决策；当前页只读投影更新不重置草稿、焦点、编辑会话或阅读锚点。

前端 `selectBook()` 先显示上次阅读页，再加载目录、全书页摘要和任务信息。初始书架统计允许暂时使用持久化值；摘要到达后重算当前书的精确统计。数据量大的完整目录仍有本地重建成本，但不再是首屏或随读窗口状态锁内的必经等待。

### 2.2 有界并发，不是盲目加线程

普通已配置单通道随读：当前页先派发，邻页最多占两个处理位置，保留新当前页容量；已在途工作仍计数，取消不能提前“释放”物理容量。开启明确配置的双通道时，各通道独立受限；不静默改用另一收费供应商。

浏览器原本已有按页数限制的 LRU，本轮增加 **16 页 + 12 MiB JSON 字符量估算**的双限制。该值不是 JavaScript 实际堆大小保证；超大页只留在当前编辑状态，不进入预取缓存。邻页 JSON 预取最多两条，不重复预取当前页；旧窗口响应、较旧 revision 和已取消请求不能反灌。

全书自动处理队列改为有游标的分批补充，每次最多考察 64 页、队列目标不超过 24，避免每次调度从头扫描几千页。

**打开书自动加载本地内容；收费 OCR 仍需本次随读会话的明确授权。** 配置了 API Key 不等于授权把每本书默默上传。授权后本会话持续翻页不重复确认。

## 3. 以本书为范围的文字推断

新增 `BookContextService`，同时接入 Qwen 局部核对、兼容的整页辅助路径和 JEV 决策上下文。

上下文包括本书标题、附近章节标题候选、当前页和前后页的可用原文，以及开头页中可用的词汇证据。最多读取 17 个不同页面；正文摘录最多 24 段、8,000 UTF-16 字符，每段有书/页/版本/块来源及 `HUMAN_REVIEWED` 或 `OCR_UNVERIFIED` 标识。章节名称是候选，不伪称已经验证。只使用本书数据，不加载 PDF、不额外发起模型调用。上下文缓存最多 128 项，页面变更使其失效。

证据优先级：原图字形与版面位置、当前局部语法、章节与邻页证据、本书主题/词汇先验。主题不是原图证据，不允许因为“符合主题”就补写图中不存在的内容。书籍正文和上下文均是数据，不是可执行指令。

Qwen 的输出仍受 owned source range、逐字 quote、UTF-16 边界和 JSON 结构校验；上下文区只读。JEV 仍只评价有限候选，允许不确定/不选，不新增正式原文，不自动接受候选。上下文在 JEV StateBuilder 哈希之前纳入，Qwen 缓存键也包含冻结的上下文、实际图片哈希、父文本、模型和提示版本，避免跨书或旧上下文误命中。

这实现的是**有界、同书、可追溯的上下文辅助**，不是已经训练出的整书主题模型，也不是全书语义索引。真实提升多少必须在人工标注的本书样本和留出样本上测量，不能编造准确率。

## 4. 当前页进度：紧接“已保存”右侧

新增 `#page-processing-progress`，是 `#page-save-status` 的紧邻兄弟节点，不覆盖正文、不弹浮层。独立的 `GET /api/books/{id}/pages/{n}/processing` 只读 attempt 元数据，返回 `Cache-Control: no-store`；没有 attempt 时返回 204，不启动、重试或上传任何内容。

百分比依据是 `WORKFLOW_MILESTONES`，不是计时器插值，不是 OCR 准确率，不是耗时预测：

| 实际事件 | 展示百分比 |
|---|---:|
| 准备/识别尚未完成 | 0% |
| 进入首个结果提交阶段 | 25% |
| 可读基线已经成功提交 | 50% |
| 分组核对实际结束 | 50%–75% |
| 校验阶段 | 至少 75% |
| 增强结果已提交 | 至少 90% |
| 成功终态且存在可读发布版本 | 100%，随后隐藏处理标记 |

外部 OCR 不提供内部细粒度进度时，显示“识别中 · 0%”而不是造出持续增长。终态包括部分完成、失败、取消、中断；“有待核对文字”与处理完成可以同时成立。阶段事件原子更新，最新 attempt 按创建先后确定，晚到子任务不能复活已结束 attempt。publishedRevision 使用提交操作实际返回的版本，不自行猜测加一。

轮询绑定书、页、请求代次和 attempt，隐藏页面降频，出错有限退避，不自动重发模型任务。Qwen 响应体有字节上限和主动关闭的截止时间看门狗，防止响应头回来后读取正文无限等待。

## 5. 已修复的其他问题

| 问题 | 修复 |
|---|---|
| 设置 API 返回密钥原文，浏览器回填 | 写入式凭据输入；只返回是否配置；空值保留，明确清除仍有效；State.toString 脱敏 |
| 取消排队 Future 跳过清理；逻辑取消提前释放在途登记 | 取消标记/中断与物理工作结束分离；finally 释放租约与登记；停机等待有限收尾 |
| 同一页旧任务未退出即再次派发 | 预约、书、页、attempt 绑定；冲突不能退回无保护的 force 队列 |
| 普通重试破坏当前页状态；可读提交版本偏移 | 随读重试保留旧页；独立 attempt；基线/增强均使用实际 CAS 版本 |
| 并发线程池队列没有明确上限 | 页面工作队列 16；Qwen 工作队列与门控均有上限；满队列明确部分完成 |
| Qwen 热刷新信号量可能扩张在途容量 | 同一组物理计数跨配置刷新保持；缩容等旧请求退出；Permit 原子关闭一次 |
| 429 退避占着并发槽、重试没有逐次计费预算 | 退避先释放槽；每次实际 HTTP 重试消耗预算；缓存不消耗调用预算 |
| 分块已经发出后失败又回退整页收费请求 | 保留原文并明确部分完成，不再在该失败路径追加整页收费调用 |
| 画像重建与保存竞争，旧结果写回缓存 | generation 发布栅栏；同书重建合并；首屏使用非阻塞快路径 |
| API 的 JSON 响应体脱离浏览器请求超时 | 在清除超时前 await response.json() |
| localStorage 返回 null、非法数组或异常数值导致打开失败 | 偏好类型校验，页码/字号/行距范围校验，书签过滤与去重 |
| 只比 localhost 主机名的伪同源、防 DNS rebinding 缺口 | 比较协议、主机、端口；拒绝 userinfo、非法 Origin、cross-site 写入；API Host 只允许本地地址 |

现有代码仍是本机单用户应用，不因增加同源检查就成为可公开暴露的多租户服务。

## 6. 密钥与历史扫描

新增 `scripts/verification/scan_secrets.py` 和持续执行的 `reader-quality.yml`。扫描当前受版本控制文件及当前 checkout 中全部可达 Git blob，包含已删除文件；报告只包含规则、路径、行号和 blob SHA，不输出匹配值。测试验证扫描器不泄露匹配内容。`.gitignore` 加入私密设置、环境配置、私钥/密钥库、凭据 JSON、测试及临时审计产物的排除规则。

正式证据以 GitHub Actions 的 `test-results/reader-audit/secrets.json` 为准：同时记录 testedCommit、工作区是否修改、文件/历史 blob 数及 findings。**零命中只代表这些规则对所扫描范围未发现密钥，不等于所有历史、不可达对象、未推送分支、Actions 缓存、开发者机器和外部平台全部安全。** 曾经泄漏的密钥需要在供应商端吊销/轮换；删除文件不能撤销泄漏，本轮没有擅自重写历史或宣称已轮换。

运行时仍可保存到数据目录下 `.settings/settings.json`，沿用 POSIX 0700 目录/0600 文件权限保护；**这不是加密存储**，Windows 权限和多人共用机器仍需独立验收。仓库中不加入真实测试凭据，在线模型测试不执行。

## 7. 设计理由与验收证据

设计采用渐进披露、相邻状态、稳定阅读锚点和低干扰反馈：保存与处理是两个状态但放在同一上下文；百分比使用等宽数字减少抖动；不闪烁、不自动抢焦点、不用大进度层遮挡正文；窄屏允许状态区折行，尊重 reduced-motion。这里描述的是设计理由，不虚构用户实验、眼动实验或注意力节省比例。

新增/加强测试覆盖并发计数、最新 attempt、真实发布版本、刷新门控不超发、重复关闭、预算约束、同书上下文、有界首屏、密钥不回显、同源检查、阻塞响应体截止时间、429 释放槽、LRU 双限制、旧翻页响应和不隐式开启收费调用。

本地编译使用 Java 17 目标字节码、JDK 21 测试运行时及由仓库 CI 解析的依赖；正式发布以 GitHub Actions 的 Java 17 `mvn verify`、Node 探针和 Python 测试为准。不得把工作区测试结果冒充另一个 commit 的 CI 结果。

真实浏览器尝试在当前审查环境被 `ERR_BLOCKED_BY_ADMINISTRATOR` 阻止：1440/390 像素视觉验收、截图和真实浏览器焦点检查记为 **BLOCKED**，不是 PASS。真实 OCR/JEV 留出集准确率、整本大书 P95 首屏/跨页时延、峰值内存、供应商限流压测、多操作系统检查记为 **NOT_RUN**。增加并发并不构成性能倍数保证。
